# 5. THE MOST IMPORTANT REQUIREMENT: DUAL FRONTEND ARCHITECTURE

The UMUM project must have both a server-rendered Django website and a REST API.

They must be two different presentation layers connected to the same business logic.

Architecture:

```text
             UMUM PLATFORM
                    |
          ---------------------
          |                   |
          v                   v
    DJANGO WEBSITE       REST API
    Django Templates     Django REST Framework
          |                   |
          v                   v
    Web Controllers      API Controllers
          |                   |
          ---------+-----------
                   |
                   v
             SERVICES
             Business Logic
                   |
                   v
              REPOSITORIES
              Data Access
                   |
                   v
                MODELS
                   |
                   v
               PostgreSQL
```

Both frontends must use the same Services and Repositories.

For example:

When a user creates an advertisement:

- A web user submits an HTML form.
- Django Web Controller validates the request.
- The controller calls ListingService.
- ListingService applies the business rules.
- ListingRepository saves the advertisement.
- Django Template displays the result.

When an API client creates an advertisement:

- The client sends a JSON request.
- Django REST Controller validates it using a DRF Serializer.
- The controller calls the same ListingService.
- ListingService applies exactly the same business rules.
- ListingRepository saves the advertisement.
- The API returns a JSON response.

The creation logic must exist only once.

Never implement separate advertisement creation logic for the website and API.

The same principle must apply to registration, favorites, payments, chat, moderation, and other business operations.
